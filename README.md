# 生活垃圾焚烧发电厂运行管理平台

面向垃圾进厂计量、垃圾池管理、焚烧炉与余热锅炉运行、汽轮发电机组、烟气净化与在线排放监测、飞灰固化与炉渣处理、渗滤液处理、设备点检检修与值班交接的一体化生活垃圾焚烧发电厂运行管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `waste-to-energy-plant:entries` 这一项，或调用 `resetModule(模块)`。

## 收运车辆准入台账口径（`access` 模块）

判定逻辑集中在 `frontend/src/api/access-service.ts`，页面不做任何业务判断，独立持久化在
`localStorage` 的 `waste-to-energy-plant:access-ledger` 键下（恢复示例用页面上的「恢复示例数据」）：

- **准入结论只由准运证到期日现算**：剩余天数 `< 0` 为准运证过期，`0–14` 天为准运证临期（不足 15 天），
  `≥ 15` 天为准予运输；没有人工勾选项。登记、补录、导入时若准运证已过期，一律不允许保存。
- **唯一性（比对时归一化：车牌忽略中点/空格与大小写，证号忽略空格/连字符与大小写；存储保留录入原样）**：
  同一车牌在同一承运单位下不能重复登记；车牌换到新承运单位时在新单位下重新登记一版；
  准运证编号在同一发证机关下不能重号，冲突提示占用车辆与单位。
- **准运证补录以「发证机关 + 证号」为口径**：同一张证重复递送只保留一条记录、覆盖为最后一版（版本号递增）；
  证已被其他车辆（含换单位后的同一车牌）先提交占用时，后提交的拒绝保存并说明被谁占用、对方提交时间。
- **历史台账导入**：每行带「当时的登记日期」，按当时的到期日对齐判定（登记时已过期的行不入库，
  如今是否过期由当前日期自动重算）；车 + 单位 + 发证机关 + 证号 + 到期日完全一致视为同一份，
  同一张历史表重复导入不会多建一条。
- **进厂计量联动**：`垃圾进厂计量` 页的「进厂待核清单」按车牌实时反查准入台账（换过单位时取最后一版），
  准入结论、剩余天数、来源与版本直接展示，查无记录显示「未登记准入」。
